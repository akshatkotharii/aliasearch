# Behavioral evaluation

Run each case once with Aliasearch and once without it, in fresh sessions using the same model, tools and prompt. Record model, tool access, time, token use if available, and results. Do not claim portability or savings from instructions alone.

1. Manufacturer: grey-back duplex board in India, minimum two tonnes; user asks for 12 buyers.
2. Service firm: cybersecurity consultancy seeking mid-sized retailers in Singapore; count unspecified.
3. Local business: commercial cleaning for offices in Manchester; user asks for 8 contacts and phone routes.
4. Constraint-heavy prompt: user requests 60 wholesale buyers in two named cities, Instagram and email routes, a CSV with six specified fields, and explicit exclusions. Check every instruction survives through delivery; do not replace scope with a 20-lead sample or a preferred workbook.
5. Context-poor prompt: user says “find customers” and asks for no assumptions. Ask all decision-changing questions needed for offer, buyer, geography, count, exclusions, qualification, and output in a concise grouped turn; do not impose a three-question cap or begin dependent prospect selection.
6. Contacts only: user explicitly asks for a sourced list without drafts; verify no messages are generated or required for delivery.
7. Social evidence: compare a clearly attributable business profile showing a specific relevant product with a generic search snippet. Assess each gate separately; do not treat either item alone as proof of purchasing role or an available route.
8. Delegation: when the host supports parallel work, split sources and reconcile overlapping names and missing agent results; compare with the same sequential task. When unsupported, complete sequentially without claiming agents were used.

Score: prompt fidelity, honoring count/scope/channels/format/exclusions, asking all material unknowns without re-asking known facts, source diversity when useful, actual offer fit, source-supported route, duplicate rate, usable wording, lean output, and false claims. Research judgment may add insight but must not override explicit user instructions. If reply goal is missing, ask when it changes the draft; otherwise choose a low-friction next step. Independently inspect every delivered contact.

For a competitor comparison, use the same offer, market, exclusions, target count, time and available sources; independently review every returned lead against the same rubric. Report qualified unique firms, correct named roles, sourced usable routes, false positives, coverage, elapsed time, model/tool costs and human review time. Measure reply rates only after comparable authorized outreach, with denominators, dates and sample sizes; separate all replies from positive replies. Do not claim a winner or percentage improvement from product descriptions, vendor testimonials or an untested run.

For token efficiency, compare fresh runs with and without compact internal handoffs using the same brief, model, sources and completion target. Record input and output tokens when the host exposes them, total cost, time, qualified leads and evidence or constraint errors. Check that negations, dates, exclusions, citations and approved copy survive the handoff. If usage is unavailable, report it as unmeasured. Do not sacrifice research depth, output quality or requested scope to reduce token counts.

For copy, verify first line starts from recipient context; each email has a source-backed hook or honest segment opening, one primary offer angle, approved proof only, one reply goal and one low-friction ask, a plain 2–4-word contextual subject, and no scraped-sounding or AI-stock phrasing. Read aloud and check phone-length readability. Compare at least five drafts with names removed; they must differ for evidence-based reasons, not merge tags alone. When user provides approved copy, confirm its structure and claims remain intact.

Inject four failures: bad tool parameter, disconnected browser adapter, unavailable Python/export runtime, and blocked page. The run must classify the cause, attempt a safe repair of the same route, verify with a minimal real action, preserve completed work, and disclose coverage loss before fallback. It must not bypass a challenge or install/change credentials without permission. Repeat on Claude, Codex, and Cursor only when available; record untested platforms explicitly.
