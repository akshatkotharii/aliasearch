# Behavioral evaluation

Run each case once with Aliasearch and once without it, in fresh sessions using the same model, tools and prompt. Record model, tool access, time, token use if available, and results. Do not claim portability or savings from instructions alone.

1. Manufacturer: grey-back duplex board in India, minimum two tonnes; user asks for 12 buyers.
2. Service firm: cybersecurity consultancy seeking mid-sized retailers in Singapore; count unspecified.
3. Local business: commercial cleaning for offices in Manchester; user asks for 8 contacts and phone routes.

Score: essential questions (maximum three per turn), honoring requested count, source diversity when available, actual product fit, source-supported route, duplicate rate, usable wording, lean output, and false claims. If reply goal is missing, ask only when it changes the draft; otherwise choose a low-friction next step. Independently inspect every delivered company.

For copy, verify first line starts from recipient context; each email has a source-backed hook or honest segment opening, one primary offer angle, approved proof only, one reply goal and one low-friction ask, a plain 2–4-word contextual subject, and no scraped-sounding or AI-stock phrasing. Read aloud and check phone-length readability. Compare at least five drafts with names removed; they must differ for evidence-based reasons, not merge tags alone. When user provides approved copy, confirm its structure and claims remain intact.

Inject four failures: bad tool parameter, disconnected browser adapter, unavailable Python/export runtime, and blocked page. The run must classify the cause, attempt a safe repair of the same route, verify with a minimal real action, preserve completed work, and disclose coverage loss before fallback. It must not bypass a challenge or install/change credentials without permission. Repeat on Claude, Codex, and Cursor only when available; record untested platforms explicitly.
